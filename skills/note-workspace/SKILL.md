# 笔记工作区技能

## 目标

把笔记工具（`note_tool`）用作可靠的外部记忆：该记的及时记、记的内容可回溯、ID 永不臆造。

## ID 纪律（最高优先级）

- `noteId` **只能**来自 `note_tool(action="create")` 或 `note_tool(action="list")` 的返回值；
- 严禁凭语义编造 ID（如把标题转成 kebab-case 当 ID 用——那不是 ID）；
- 忘记 ID 时先 `action="list"`（可带 keyword 过滤）找回，再继续追加；
- 报错"目标不存在"时，第一步永远是 list 核对，而不是换一个编造的 ID 重试。

## 工作流

1. **建卡**：任务开始需要留痕时，`action="create"` 建笔记（标题带主题与日期），**立即把返回的 Note ID 记入后续所有调用**。
2. **追加**：每个阶段性发现立即 `action="append"` 追加——单次追加一个完整片段，不要拆成碎片。
3. **回顾**：交付前 `action="get"` 取回全文，基于笔记总结提炼，不凭记忆复述。
4. **善后**：仅在用户明确要求时 `action="delete"`（需用户放行）；早期记录有严重错误时 `action="update"` 整体重写（先 get 备份要点）。

## 追加内容结构（每条记录统一格式）

```
[来源: URL 或"本地分析"] 一句话核心发现
- 关键数据 / 论据（有则必录）
- 对任务的判断：相关 / 不相关 / 待验证
```

## 记录时机

- 每读完一个有价值的页面（含无关页面——记下"为什么无关"可避免重复探索）；
- 每得到一个中间结论或数据交叉结果；
- 每次失败的尝试（换关键词、被拦截的链接）；
- 任务交付前：把最终完整重要结果（结论、关键数据、有效来源清单）追加进笔记，形成可复用沉淀。

## 边界

- 笔记是记忆不是稿库：原文大段搬运没有价值，提炼后的事实与判断才是；
- 任务步骤与执行状态不用笔记承载：要做哪些步骤、做到哪了，交给 plan_tool（会话计划，输入区上方实时可见），笔记只沉淀知识与证据；
- 用户没有要求整理时不要主动删除/重写笔记；
- 笔记过长（数千字）影响回顾时，可在交付后建议用户拆分。
