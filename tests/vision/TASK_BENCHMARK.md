# 视觉任务回归方案

驱动夹具测试和真实模型端到端测试分别记录。已知DOM坐标命中证明驱动映射，不证明模型能辨认同样小的目标。

## 自动化命令

- `npm run test:vision`：坐标边界、裁剪映射、参数防御、守卫、焦点抢占、取消、清理和错误诊断。
- `node tests/vision/browser-probe.mjs`：独立临时Chromium中的生产驱动与实际PNG裁剪、点位、滚轮、输入、iframe、DOM检查。
- `npm run test:tools`：工具注册、预设、测试目录、能力边界与文档防漂移。
- `npm run test:contract`：模型适配协议、图片传递与错误路径。
- `npm run test:image-context`：图片上下文和引用行为。
- `npm run compile`、相关ESLint、生产构建。

## 后续真实模型任务集

固定网页版本、浏览器版本、窗口/DPR、模型/服务配置、初始数据和每任务时间/轮数预算，每个配置至少重复多次。
可以复用browser-probe中的合成控件，在不含真实账号和不可逆交易的测试环境中执行。

| 任务 | 成功证据 | 重点记录 |
| --- | --- | --- |
| 密集小按钮 | 正确按钮的事件计数变化，邻近按钮未触发 | 是否先放大，crop坐标是否携带viewId；不要要求模型必然看准1px |
| 中文与emoji表单 | 非密码字段值与预期相符，校验反馈通过 | Unicode模式、字符/字素数量、页面是否拒绝输入 |
| 键盘驱动编辑器 | 值与键盘事件均符合预期 | keys/text模式选择、布局限制、Enter单独处理 |
| 嵌套纵横滚动 | 指定容器偏移变化，外层保持预期状态 | 到边界、滚动吸附、事件派发量与实际偏移的区别 |
| 动态/遮挡目标 | 不误点覆盖层；变化后重截图或守卫拒绝 | TARGET_CHANGED后是否盲目重试，Canvas是否被误当成DOM已验证 |
| 自由路径与拖放 | 所有节点被经过，终点和业务drop状态符合 | 默认弯曲与显式直线、HTML5/drop事件、失败释放 |
| iframe与自定义组件 | 正确frame内控件产生预期状态 | 局部rect是否误当成顶层坐标、证据不足时是否报告unknown |
| 异步结果 | 显式成功标识出现后才报告完成 | 仅readyState/几何稳定是否被误当成业务成功 |
| 中止与恢复 | 无持续输入或被按住状态；恢复先观察 | 已派发进度、最后事件不确定性，是否整段重输/重复提交 |
| 只读助手权限 | 仅阅读/滚动/观察，未触发输入或点击 | 动态技能不能突破只读工具上限 |

## 结果记录

每次至少记录：任务ID、模型/配置、浏览器/DPR、开始结束时间、最终状态、成功证据、工具调用数、观察/动作数、错误码、恢复次数、耗时与实际token使用。
最终状态区分：成功、明确失败、证据不足、需要用户、取消。不要把工具success率当成任务成功率。
误操作率与“错误宣称完成”率必须单独统计。记录基准时不要保存真实密码、文件私密内容或完整认证信息。
固定任务预算后才能比较版本或其他系统；工具列表更长或单个演示通过，不构成总体能力领先的证据。
